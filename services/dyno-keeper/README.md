# Project DYNO keeper

The keeper is dry-run unless `DYNO_KEEPER_LIVE=true`. It reads chain state before every action and can request randomness after freeze, finalize winners, settle, execute only the current DCA slot, mark elapsed slots missed, and close after the seven-day boundary. Prize delivery is manual and never scheduled by the keeper. The contracts enforce all choices and amounts.

It loads the committed generated ABI package, not Hardhat build artifacts; production-only installs can start without dev dependencies or compiler output. Regenerate that package after any contract ABI change and review it with the implementation.

By default the keeper reads `activeRoundId` from the manager at each tick, so a later round does not require a service setting change. `DYNO_ROUND_ID` may pin a positive round ID for a controlled run. The health response records which round was checked. This does not replace the pending-transaction, nonce/replacement, finalized-state, and backup-takeover hardening still required before live signing.

Live ticks now send at most one action, recheck the planning block hash and refuse to send while the gas wallet has a pending nonce. The current hourly buy is prioritized over housekeeping for expired slots. A receipt wait is bounded to 45 seconds. Live signing requires an absolute `DYNO_KEEPER_JOURNAL_PATH` on a persistent private disk. The keeper atomically records an intent before submission and its hash/receipt afterward; a restart reconciles a known hash. An unresolved intent, including a crash after preparation but before recording the hash, **stops new sends** for operator investigation. Never delete or edit that journal merely to clear an alert: compare chain nonce, transaction, slot status and receipt first. The nine focused keeper checks cover restart blocking and a later receipt, not a complete fee-replacement or backup-takeover policy. Do not turn on `DYNO_KEEPER_LIVE` until those paths and market/VRF integrations are reviewed.

Run primary and backup instances with separate gas wallets and separate persistent journal paths, and only the on-chain keeper role. Never point two live processes at the same gas wallet/journal. Use a process supervisor with restart-on-failure. Alert when the health endpoint is stale, VRF is pending over 24 hours, review is stalled, either gas wallet is low, a slot fails/misses, an upgrade event appears, a transfer remains unpaid, or reconciliation reports insolvency. Backup takeover means starting the second process after checking the current chain slot and the primary wallet's unresolved intent; never replay an earlier DCA slot.
